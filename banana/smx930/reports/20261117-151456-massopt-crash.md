## New v0.12.1 features implicated versus exonerated

1. `DM_VK_PREWARM=1` performed 150 expensive compiles during the intro and was stopped by its memory floor. It competes for CPU and memory and overlaps the AAudio stream disconnects. This warrants an isolated test with `DM_VK_PREWARM=0`; **causation is not proven**.
2. `DM_VK_SLOT_POOL=1` activated and logged no pool-reset failure, fence timeout abort, or device loss. We cannot assert it is safe in all later scenes; leave it enabled only for the first isolated experiment, then compare disabled if needed.
3. The separate driver pipeline cache reached 19.9 MiB and was saved persistently. **Do not clear APK app data, shader pack, or driver cache**; doing so discards hundreds of cached pipeline compiles.
4. File-backed guest shader/texture pools remain enabled. Post-intro long frames include many major page faults and memory allocations. A second-stage audit should distinguish hard fault latency, guest compute work, and Vulkan allocations. Do not disable fileback as an unmeasured memory-risk experiment.

## Recommended controlled recovery

**Use the existing MassOpt v0.12.1 APK**, same faux123 v1.1.8 driver, game and resolution. In Game → Performance → Advanced → Extra environment put only:

```
DM_VK_PREWARM=0
```

It overrides one experimental default and retains all caches, including the ~20 MiB compiled Vulkan pipeline cache. If the next run still fails, isolate command-pool mode separately (`DM_VK_SLOT_POOL=0`) rather than toggling both at once. To confirm Android termination, capture filtered `lmkd`/AndroidRuntime/tombstone logs with ADB before reproducing; the app's digest is not sufficient proof of OOM.

## Future code changes by measured priority

- CPU/replay: attribute the ~228.6 ms/frame unclassified work in `vka_exec.c`; include workload categories and guest memory faults, without adding log spam in the frame loop.
- Queue submissions: profile the ~6/frame and ~10 ms/frame PanVK driver CPU submission time; merge only proven-safe independent command batches.
- First-3D: stage nonblocking pipeline compilation earlier **without harming video playback or competing with Android audio**; persist per-driver Vulkan cache and prewarm keys across APK updates.
- Memory: budget guest file-backed pools and transient Vulkan allocations jointly, and capture system LMKD cause.
