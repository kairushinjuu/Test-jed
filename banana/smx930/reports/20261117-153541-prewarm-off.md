# SM-X930 MassOpt v0.12.1 — 15:35:41 crash diagnosis

## Evidence
- User-owned private Drive log `0400486024DEC000-20261117-153541.log` (1,658 lines) and matching digest.
- Build `banana-mali-g925-20261117@09e8c1b`, PanVK faux123 v1.1.8, `DM_VK_PREWARM=0` explicitly overrode default; prepared 42,848-shader library found. `DM_VK_SLOT_POOL=1` remained enabled.
- Intro AV1 end-of-stream occurred. Process terminated abruptly during first 3D scene; digest says Android closed it **without identifying a cause**. No native tombstone or LMKD proof is present in this log.

Unlike earlier windows, the new log identifies a **212 ms GPU part** at frame 10196; a window median of 1.4 ms GPU busy does NOT mean all gameplay GPU work is that cheap.

## Newly localized costs
- At the last pace sample (frame 10198): 117.2 ms total replay recording, with 68.1 ms replay CPU time. `other records` cost 85.3 ms/frame, 435 draw calls/frame and around 6.4 queue submits/frame. Native encoder reports `dispatches 42.55 ms (27 calls)`, and a 0.5-second wait on the encoder thread. This is a significant hot path; the encoder wait's instantaneous tail/head values do not establish a deadlock.
- The Mali driver requires ~10.6 ms/frame in queue submissions again, unchanged. A GPU part lasting 212 ms suggests a transient GPU-side spike in addition to host recording stalls.
- Tracked graphics memory rapidly grew 1,327 -> 1,825 -> 2,491 -> 2,856 MiB, including a 12,288×12,288 297 MiB image, and memory map count reached 51% of `vm.max_map_count`. 11,849 small `/dev/mali` maps plus several thousand guest maps. A link to Android LMKD is not proven.
- The compiled PanVK pipeline cache remained ~20.9 MB and is being reused; 71 pipelines made this run. Disabling prewarm did not remove all background optimization tasks (they may be demand-driven).

## Decision
**Prewarming is not a sole cause of the crash.** Keep it off for one further controlled run and disable **only** the experimental per-slot command pools (`DM_VK_SLOT_POOL=0`) to compare against current state. Avoid changing the GPU driver, graphics scale, shader library or other scheduling settings. If stability still fails, restore code-level tracing of `vka_exec.c`, `vka_enc.c`, NVN memory allocations and GPU fragment/compute dispatches, not more generic shader toggles. A single run cannot exonerate or implicate the slot-pool feature; v0.8 also crashed before it was added.

## Low-memory evidence
Run the existing `banana/smx930/tools/collect-adb.sh` from a trusted ADB host before launching to record targeted low-memory termination and memory pressure, if available. The game log/digest alone does not explain the kill. Do not upload raw logcat to public GitHub.
