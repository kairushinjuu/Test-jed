## Memory-pressure behavior

- The 128MiB refresh rule is running; it is **not** failing to activate.
- Image cache pressure at line 795: 1,092MiB images, 1,073MiB protected recent working set, MemAvailable 1,107MiB (reserve target 1,536MiB); 15 images reclaimed (~6.9MiB).
- Line 903: 1,220MiB images, 1,175MiB working set, MemAvailable **826MiB**, considerably below the configured reserve; pressure label says `no memory pressure: the RAM rule` despite low available memory (inspect accounting/control-path labeling, not necessarily a functional bug).
- Line 960: 34 older images evicted (~19.8MiB), 490 live / ~1,784.4MiB, limit 1,790MiB. Large live image set, many newly GPU-written or currently used assets, cannot be removed blindly.
- Largest single tracked texture: 12,288×12,288 / 297MiB game render target. This is not evidence of a leak alone.
- Process had 40,817 memory mappings at peak, below the *assumed* default limit of 65,530. No definitive VMA exhaustion found.

## Engineering decisions

1. **Do not claim v0.17 fixes the crash or measurably speeds v0.16**. Cold pipeline caches are different, frame indexes/workloads differ, and neither was playable in stable 3D.
2. The live-set/budget mechanism appears to be actively functioning, but cannot evict GPU-owned or recent images without correctness hazards. Budget refresh alone is insufficient.
3. Next source-level audit: attribute major faults to shader/texture file-backed pools versus general game file I/O with native counters (`mincore`/fault deltas where feasible), and measure RAM/swap/zram/PSI and guest pool resident bytes at heavy transition. Investigate bounded texture-fileback opt-out (`DM_MEM_FILEBACK_KINDS=shader`) only as isolated, guarded experiment; may *increase anonymous RAM usage and OOM risk*. Do **not** automatically recommend as successful fix.
4. Audit pipeline cache persistence and first-scene pipeline creation: v0.17 first run creates a separate cold cache; preserve it, never uninstall/clear app data. Consider avoiding a new package ID on every iteration once a stable signing workflow is secured; do not bypass Android signer validation.
5. Obtain actual Android exit reason from ActivityManager/lmkd/`ApplicationExitInfo` with the existing ADB collector; launcher digest's OOM is not enough.
6. Avoid another identical user test until a causally-targeted source change, instrumentation, or controlled A/B is available.
